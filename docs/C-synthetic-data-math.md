# C — Synthetic Data Generation: Mathematics and Design

This document explains the mathematical foundations behind the synthetic dataset generated by `data_processor.py`: the probability distributions used for each feature, the logistic model used to generate churn labels, and the stratified train/test split.

Related documents: [Data Pipeline](06-data-pipeline.md) | [Random Forest Deep Dive](A-random-forest-deep-dive.md)

---

## 1. Why a Logistic Model for Data Generation?

The goal is to generate a dataset where the features have a **realistic, non-trivial relationship** with the churn label — not random noise, but also not a perfectly separable dataset that any model would solve trivially.

A logistic model is the natural choice because:
- It produces probabilities between 0 and 1 (valid for a binary outcome).
- The relationship between features and outcome is smooth and continuous.
- The coefficients directly encode the direction and strength of each feature's effect.
- Adding Bernoulli noise on top of the probability creates realistic label noise.

## 2. Feature Distributions

### `account_age` — Discrete Uniform Distribution

```python
account_age = rng.integers(1, 73, size=n_rows)
```

`rng.integers(low, high, size)` draws integers uniformly from `[low, high)`, so values range from 1 to 72 inclusive.

**Distribution:** `account_age ~ Uniform{1, 2, ..., 72}`

Each value has equal probability `1/72 ≈ 1.4%`. This models a customer base where subscription lengths are evenly spread from 1 month to 6 years.

### `monthly_spend` — Clipped Normal Distribution

```python
monthly_spend = np.round(np.clip(rng.normal(100, 30, size=n_rows), 20, 250), 2)
```

**Step 1 — Normal distribution:** `rng.normal(loc=100, scale=30)` draws from:

```
monthly_spend ~ N(μ=100, σ=30)
```

The **normal (Gaussian) distribution** is parameterised by mean `μ` and standard deviation `σ`. About 68% of values fall within one standard deviation of the mean (70–130), and 95% within two standard deviations (40–160).

**Step 2 — Clipping:** `np.clip(x, 20, 250)` replaces any value below 20 with 20 and any value above 250 with 250. This prevents unrealistic negative or extreme spend values. The clipping affects only the tails of the distribution (values more than 2.67σ from the mean).

**Step 3 — Rounding:** `np.round(x, 2)` rounds to 2 decimal places, simulating real monetary values.

**Result:** A roughly bell-shaped distribution centred at $100, bounded between $20 and $250.

### `support_tickets` — Poisson Distribution

```python
support_tickets = rng.poisson(2.5, size=n_rows)
```

**Distribution:** `support_tickets ~ Poisson(λ=2.5)`

The **Poisson distribution** models the number of events occurring in a fixed interval when events happen at a constant average rate `λ`. It is the natural distribution for count data (number of tickets, number of purchases, number of logins).

**Key properties:**
- Mean = λ = 2.5
- Variance = λ = 2.5 (mean equals variance — a defining property of Poisson)
- Values are non-negative integers: 0, 1, 2, 3, ...
- P(k events) = (λ^k × e^(-λ)) / k!

**Example probabilities for λ=2.5:**

| k (tickets) | P(k) |
|-------------|------|
| 0 | 8.2% |
| 1 | 20.5% |
| 2 | 25.6% |
| 3 | 21.3% |
| 4 | 13.3% |
| 5+ | 11.1% |

Most customers raise 1–3 tickets, with a long tail of high-ticket customers.

## 3. The Logistic Model for Churn Probability

### The Logit (Log-Odds)

The churn probability is generated using a **logistic regression model**. The first step computes the **logit** — the log-odds of churning:

```python
churn_logit = (
    -1.3
    - 0.025 * (account_age - 36)
    + 0.012 * (monthly_spend - 100)
    + 0.45 * (support_tickets - 2.5)
)
```

This is a linear function of the **centred** features:

```
logit(p) = β₀ + β₁(x₁ - μ₁) + β₂(x₂ - μ₂) + β₃(x₃ - μ₃)
```

Where:
- `β₀ = -1.3` — intercept (baseline log-odds when all features are at their mean)
- `β₁ = -0.025`, `x₁ = account_age`, `μ₁ = 36` (mean of Uniform{1,72})
- `β₂ = +0.012`, `x₂ = monthly_spend`, `μ₂ = 100` (mean of N(100,30))
- `β₃ = +0.45`, `x₃ = support_tickets`, `μ₃ = 2.5` (mean of Poisson(2.5))

**Why centre the features?** Subtracting the mean means the intercept `β₀` represents the log-odds when all features are at their average values, making it directly interpretable.

### The Logistic (Sigmoid) Function

```python
churn_probability = 1 / (1 + np.exp(-churn_logit))
```

The **logistic function** (also called the **sigmoid function**) maps any real number to the interval (0, 1):

```
σ(z) = 1 / (1 + e^(-z))
```

**Key properties:**
- `σ(0) = 0.5` — when logit = 0, probability = 50%
- `σ(z) → 1` as `z → +∞`
- `σ(z) → 0` as `z → -∞`
- The function is symmetric: `σ(-z) = 1 - σ(z)`
- Derivative: `σ'(z) = σ(z) × (1 - σ(z))`

**Visualising the sigmoid:**

```
z:    -4    -3    -2    -1     0    +1    +2    +3    +4
σ(z): 0.02  0.05  0.12  0.27  0.50  0.73  0.88  0.95  0.98
```

### Baseline Churn Rate

When all features are at their mean values, the logit equals the intercept:

```
logit = -1.3
churn_probability = σ(-1.3) = 1 / (1 + e^1.3) = 1 / (1 + 3.669) ≈ 0.214
```

So the baseline churn rate is approximately **21.4%**. This is a realistic SaaS churn rate.

### Effect of Each Feature

**`account_age` (coefficient = -0.025):**

Each additional month of account age decreases the logit by 0.025. A customer who has been subscribed for 72 months (6 years) vs. 1 month:

```
Δlogit = -0.025 × (72 - 1) = -0.025 × 71 = -1.775
```

This corresponds to a large reduction in churn probability. Long-tenured customers are much less likely to churn — a well-known pattern in SaaS businesses.

**`monthly_spend` (coefficient = +0.012):**

Each additional dollar of monthly spend increases the logit by 0.012. A customer spending $250 vs. $20:

```
Δlogit = 0.012 × (250 - 20) = 0.012 × 230 = +2.76
```

Higher-spending customers churn slightly more. This could model customers who are on expensive plans and more likely to evaluate alternatives.

**`support_tickets` (coefficient = +0.45):**

Each additional support ticket increases the logit by 0.45. A customer with 8 tickets vs. 0 tickets:

```
Δlogit = 0.45 × (8 - 0) = +3.6
```

This is by far the strongest predictor. Customers who raise many support tickets are much more likely to churn — they are experiencing problems with the product.

### Worked Example

Customer: `account_age=12`, `monthly_spend=89.5`, `support_tickets=3`

```
logit = -1.3
      - 0.025 × (12 - 36)     = -0.025 × (-24) = +0.600
      + 0.012 × (89.5 - 100)  = +0.012 × (-10.5) = -0.126
      + 0.45  × (3 - 2.5)     = +0.45  × 0.5 = +0.225
      = -1.3 + 0.600 - 0.126 + 0.225
      = -0.601

churn_probability = σ(-0.601) = 1 / (1 + e^0.601) = 1 / (1 + 1.824) ≈ 0.354
```

This customer has a 35.4% probability of churning — above the baseline (21.4%) because of the 3 support tickets, but moderated by the relatively young account age (12 months is below the 36-month mean, which actually *increases* churn risk since the coefficient is negative).

This is the same customer used in the `curl` example in the README and in `predict_remote.py`.

## 4. Bernoulli Sampling: Adding Realistic Noise

```python
churn = rng.binomial(1, churn_probability)
```

`rng.binomial(n=1, p=churn_probability)` draws from a **Bernoulli distribution**: returns 1 with probability `p` and 0 with probability `1-p`.

This is applied element-wise across all 1,000 customers. Each customer's churn label is an independent random draw from their individual probability.

**Why this matters:** Without this step, the churn label would be deterministic (e.g., churn if probability > 0.5). The Bernoulli sampling introduces **label noise** — some high-risk customers don't churn, and some low-risk customers do. This makes the classification problem realistic and non-trivial.

**Effect on the dataset:** The actual churn rate in the generated dataset will be approximately 21.4% (the baseline), but will vary slightly due to random sampling. With `random_state=42`, the exact count is fixed.

## 5. Stratified Train/Test Split

```python
train_data, test_data = train_test_split(
    dataset,
    test_size=0.2,
    random_state=42,
    stratify=dataset[TARGET_COLUMN],
)
```

### Why Stratification Matters

Without stratification, a random 80/20 split might produce:
- Training set: 22% churners
- Test set: 16% churners

This would make the test set unrepresentative of the true distribution, leading to unreliable evaluation metrics.

**Stratified splitting** ensures the class ratio is preserved in both splits. If the full dataset has 21% churners:
- Training set (800 rows): ~21% churners (~168 churners)
- Test set (200 rows): ~21% churners (~42 churners)

### How It Works

scikit-learn's `train_test_split` with `stratify=y`:
1. Separates the dataset into groups by class label.
2. Splits each group independently at the specified ratio.
3. Combines the splits.

For a dataset with 214 churners and 786 non-churners:
- Churners: 171 to train, 43 to test (80/20)
- Non-churners: 629 to train, 157 to test (80/20)
- Combined: 800 train, 200 test

## 6. Reproducibility: The Role of `random_state=42`

Three separate random operations use `random_state=42`:

| Operation | Where | Effect |
|-----------|-------|--------|
| Data generation | `generate_data(random_state=42)` | Same 1,000 rows every time |
| Train/test split | `train_test_split(..., random_state=42)` | Same 800/200 split every time |
| Model training | `RandomForestClassifier(random_state=42)` | Same 200 trees every time |

The value 42 has no special mathematical significance — it is a conventional choice. Any fixed integer would produce equally reproducible results.
